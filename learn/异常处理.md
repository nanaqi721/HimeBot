# 异常处理相关问题



## 异常筛选器的语法以及为何使用异常筛选器

异常筛选器的行为是：

```
catch (Exception exception) when (
    exception is ArgumentException
    or NotSupportedException
    or PathTooLongException)
```

如果抛出 `PathTooLongException`：

```
筛选条件为 true → 进入 catch → 返回失败结果
```

如果抛出其他异常，例如 `OutOfMemoryException`：

```
筛选条件为 false → 当前 catch 跳过 → 向调用者继续抛出
```

**但这不意味着应该改成：**

```
catch (Exception exception)
{
    return new GameLaunchResult(false, exception.Message);
}
```

**因为这样会把程序错误也伪装成普通的“路径错误”。例如空引用、代码逻辑错误、内存不足，都不应该被描述成“游戏启动目标路径无效”。**

这里采用的原则是：

- 能够预料、用户可以纠正的路径错误：在这里处理并显示提示。
- 没有预料到的程序错误：继续抛出，便于开发时发现并修复。
- 如果以后确认某个新异常属于正常且可恢复的业务情况，再有针对性地加入处理。

所以当前代码确实可能因意外异常终止，但这是有意区分“可恢复的输入错误”和“真正的程序故障”，而不是漏写一个万能 `catch`。
